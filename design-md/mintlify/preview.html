Quickstart: Real-time Event Ingestion

Learn how to authenticate and stream your first batch of microsecond events into the AetherDocs telemetry bus. Within minutes, your applications can publish structured payloads to partitioned edge topics.

1. Prerequisites & Environment

Before executing telemetry requests, verify that you have obtained your project API key and configured an ingestion environment:

  • An active Aether workspace with an initialized organization ID
  • API credentials with events:write permission scope
  • Node.js version 18.0+, Python 3.9+, or Go 1.20+ installed on your local workstation
Development Key Availability

For local debugging, you can utilize the public sandbox key aether_test_99f2e7b1. It includes a soft rate limit of 100 requests per minute with automatic data purging every 6 hours.

2. Install the Client Library

Install the official lightweight driver for your runtime platform. The package bundles zero native dependencies and includes compile-time TypeScript signatures: 

$ npm install @aetherdocs/telemetry-sdk

3. Send an Ingestion Payload

Initialize the client with your key and emit a structured event. The SDK validates payloads against your team's schema registry before dispatching over persistent HTTP/2 keep-alive sockets:

main.ts 
import { AetherClient } from '@aetherdocs/telemetry-sdk';

// Initialize client instance with your scoped project token
const client = new AetherClient({
  apiKey: process.env.AETHER_API_KEY || 'aether_test_99f2e7b1',
  region: 'us-east-1',
  flushIntervalMs: 250, // Auto-batch every 250ms
  retryCount: 3
});

// Dispatch structured event payload with telemetry attributes
async function trackUserAction() {
  const response = await client.publish({
    topic: 'user.checkout.completed',
    partitionKey: 'usr_9824_na',
    payload: {
      transactionId: 'tx_78119028',
      totalAmountUsd: 149.50,
      itemCount: 3,
      channel: 'web-storefront',
      clientTimestamp: new Date().toISOString()
    }
  });

  console.log('[Aether] Event ingested with offset:', response.offset);
}

trackUserAction();

4. Expected JSON Response

Upon successful ingest, the Aether ingest cluster acknowledges with an offset acknowledgement and trace ID:

Status 202 Accepted schema: v2.event.ack 
{
  "status": "accepted",
  "traceId": "trace_c89b21f0088921a",
  "partition": 4,
  "offset": 8940129,
  "latencyMs": 1.84,
  "idempotentReplay": false
}

Payload Parameters

The telemetry pipeline enforces strict attribute validation based on your topic definition:

Parameter Type Required Description
topic string Required The destination event stream (e.g. user.signup).
partitionKey string Required Guarantees strict ordering per partition (e.g. customer ID, account UUID).
payload object Required Arbitrary JSON or Avro object containing telemetry attributes up to 1MB.
idempotencyKey string Optional Unique token to de-duplicate retried network calls over a 24h rolling window.
Partition Key Distribution

Avoid using low-cardinality keys like region codes or static constants. Skewed partitions can lead to hot-spotting on specific edge broker nodes. We recommend hashing composite identifiers like {tenant_id}:{entity_id}.
