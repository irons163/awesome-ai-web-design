SEC_08 // COMMON INQUIRIES

Technical FAQ

Everything you need to know about specs, security models, pricing, and migration paths.

1. What exactly is a cloud software factory? ▼
A software factory is an automated, declarative infrastructure layer that spins up ephemeral microVMs containing codebases, runtimes, LLM agents, and test suites to build, fix, and verify code autonomously without blocking local machines.
2. How do you define a factory in code? ▼
Using declarative factory.yaml specs version-controlled in git. You specify connected repositories, secret managers, MCP server endpoints, evaluation criteria, and model routing policies.
3. Which frontier and open-weight models are supported? ▼
Claude 3.7 Sonnet, Claude 3.5 Sonnet, GPT-4.5, GPT-4o, DeepSeek-V3, and DeepSeek-R1, as well as self-hosted models running on your own vLLM or Ollama clusters.
4. How does Warp Factories relate to Warp Terminal? ▼
Warp Terminal is the interactive developer client. Warp Factories is the cloud infrastructure tier. You can dispatch factory jobs directly from the terminal or inspect running cloud executions in your terminal blocks.
5. How does this differ from traditional CI/CD like GitHub Actions? ▼
CI/CD runs static deterministic scripts and halts on failure. Warp factories run autonomous reasoning loops that actively fix failures, re-run tests, and write PRs before notifying engineers.
6. Where does our proprietary code and training data live? ▼
Data resides in your existing repositories and ephemeral sandboxes that are wiped on completion. LLM requests pass through zero-retention gateways, with enterprise on-prem VPC runner options.
7. Does Warp replace human software engineers? ▼
No. It automates repetitive mechanical toil—dependency updates, lint fixing, test authoring, and bug reproduction—allowing engineers to focus on architecture, product specs, and system design.
8. Can small teams start small without massive infrastructure? ▼
Yes. You can start with a single factory runner on our free tier or utilize the $10k qualified early access compute credit.
9. How is compute usage and token cost billed? ▼
Billed transparently per microVM execution minute and pass-through token costs, with strict hard budget caps and team-level quotas to prevent unexpected spend spikes.
