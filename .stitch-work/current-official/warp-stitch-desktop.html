SEC_08 // COMMON INQUIRIES

Technical FAQ

Everything you need to know about specs, security models, and migration paths.

1. What exactly is a cloud software factory? ▼
A software factory is an automated, continuous compute loop where software development lifecycle tasks (such as bug fixing, migrations, lint remediations, and code reviews) are orchestrated by AI agents inside hardened sandboxes with full deterministic evals and test runners.
2. How does Warp differ from traditional CI/CD like GitHub Actions? ▼
CI/CD executes static procedural tasks (build, test, deploy). Warp Factories execute dynamic cognitive loops with agent harnesses: reading code, identifying root causes, applying AST refactorings, re-testing, and opening verified pull requests when tests succeed.
3. Can we bring our own fine-tuned models or self-hosted LLMs? ▼
Yes. Warp's model router supports Anthropic, OpenAI, DeepSeek, Google, or any OpenAI-compatible API endpoint including self-hosted vLLM or Ollama clusters.
4. How does Warp ensure sandboxed security and credential safety? ▼
Every factory invocation runs in an isolated ephemeral Firecracker microVM with sub-second spinup. Secrets are injected at runtime through air-gapped memory, and egress internet access can be completely restricted via strict network policies.
5. What is the $10,000 early access compute credit program? ▼
Teams accepted into the Private Cohort receive $10,000 in Warp Cloud compute credits to run autonomous migration factories and evaluate SWE benchmark runs against their internal repositories.
6. Does Warp replace human software engineers? ▼
No. It automates repetitive, tedious engineering tasks—upgrades, minor bug triage, linter regressions, and initial test scaffold writing—freeing engineers to focus on architectural decisions and feature delivery.
7. How do factory evals prevent hallucinations and code regressions? ▼
An agent cannot merge or propose code without passing the exact test suite, typechecker, and linter specified in your factory.yaml specification. If a regression occurs, the failure trace is automatically fed back to self-heal the diff.
8. Can factories trigger from webhooks, Jira tickets, or Slack alerts? ▼
Yes. Warp provides webhooks and pre-built integrations with GitHub Actions, Linear, Jira, Sentry, and PagerDuty to launch factories on alerts or bug assignments.
9. What are the system requirements for self-hosted runners? ▼
Self-hosted runners require an x86_64 or ARM64 Linux host with KVM enabled for Firecracker microVM support, Docker or Podman for OCI containers, and minimum 4 vCPU / 16GB RAM.
